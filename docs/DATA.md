# Preprocessed data specification

## Download

The preprocessed data are hosted on [Hugging Face Datasets](https://huggingface.co/AnonymousButt/MoSID-data).

The version used for this release is [HF_COMMIT](https://huggingface.co/datasets/AnonymousButt/MoSID-data/tree/766b67a9640e29d7acfd37fddffbbc9036a4ad76).

Run the following commands from the MoSID source repository root on Linux:

```bash
python -m pip install huggingface_hub

hf download HF_REPO_ID \
  --repo-type dataset \
  --revision HF_COMMIT \
  --include "Movies/nm/*" \
  --include "SHA256SUMS.txt" \
  --local-dir datasets/amazon

(
  cd datasets/amazon
  sha256sum -c SHA256SUMS.txt
)
```

No Hugging Face login is required for this public dataset.

The expected directory is `datasets/amazon/Movies/nm/`. Every data file should report `OK` during checksum verification.

After downloading, follow the Stage 1 training, SID export, Stage 2 training, and evaluation commands in the source README.

Place the files in the following directory before running Stage 1:

```text
datasets/amazon/Movies/nm/
  txt_emb.pt
  img_emb.pt
  collab_emb.pt
  mod_presence.pt
  mappings.pkl
  train.pkl
  valid.pkl
  test.pkl
```

Let `N` be the number of items. Item IDs must be contiguous integers `1..N`, with ID `0` reserved for padding. All embedding, presence, SID, and sequence files must use the same item-ID mapping.

| File | Required content |
| --- | --- |
| `txt_emb.pt` | PyTorch tensor of shape `[N+1, 768]` containing text embeddings |
| `img_emb.pt` | PyTorch tensor of shape `[N+1, 768]` containing visual embeddings |
| `collab_emb.pt` | PyTorch tensor of shape `[N+1, 256]` containing collaborative embeddings |
| `mod_presence.pt` | Boolean PyTorch tensor of shape `[N+1, 2]`; columns indicate observed text and visual features |
| `mappings.pkl` | Dictionary containing `item2id`, a nonempty dictionary whose values are exactly `1..N` |
| `train.pkl` | Dictionary containing equally sized `item_seqs` and `labels` lists |
| `valid.pkl` | Same sequence/label schema as training |
| `test.pkl` | Same sequence/label schema as training |

Each `item_seqs` entry is a nonempty list of valid item IDs; its corresponding `labels` entry is the next-item ID. Histories are truncated to the last 50 items and left-padded internally. Input sequences should contain item IDs rather than SID tokens. Training, validation, and test splits must already be prepared.

Embeddings should be finite floating-point tensors. Set padding row zero to zero and both padding presence flags to false. Text and visual availability are determined by the presence tensor; the unified tokenizer masks missing content blocks and normalizes observed embeddings internally. Collaborative features are available for every non-padding item. Stage 2 also reads the raw embeddings for compatibility scoring.

The SID table, codebook weights, and `sid_unified_source.json` are generated by `scripts/export_sid.py`; they are not input requirements for Stage 1. The data directory must be writable for export. Use data files from a trusted source: the sequence and mapping files use Python pickle serialization.
